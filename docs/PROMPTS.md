# ChatGPT prompt pack

Ready-to-paste prompts (the "ChatGPT prompts" perk). Generated assets are
starting points — always review with counsel before publishing.

## Terms of Service

```
You are a SaaS legal drafter. Write a Terms of Service for a {product type}
named {product name} at {url}. It offers: {features}. Pricing: {pricing}.
The company is located in {country} and sells worldwide. Include sections
on: account terms, acceptable use, subscription & payment, cancellations
and refunds, intellectual property, termination, disclaimers, limitation
of liability, governing law, and contact information. Keep tone plain and
buyer-friendly. Flag anything that needs a lawyer's review in brackets.
```

## Privacy Policy

```
Write a Privacy Policy for a SaaS product {name} at {url}. Data collected:
account details, usage analytics {list analytics}, payment data processed
by Stripe. Hosting: {host}. Emails: {provider}. Include: data categories
and purposes, legal bases, retention, data subject rights ({GDPR/CCPA}
applicable), subprocessors, cookies, security, and a contact channel.
Flag anything requiring lawyer review in brackets.
```

## Product requirements (a la the PRD that produced this boilerplate)

```
Act as a senior product manager. Write a PRD for a {category} SaaS whose
target users are {personas}. Include: executive summary, goals/non-goals,
functional requirements with P0/P1/P2 priorities, key user journeys, data
model guidance, non-functional requirements, MVP definition with exit
criteria, post-MVP roadmap, and acceptance criteria. Be specific and
treat P0 as "required to sell".
```

## Landing page copy

```
Write landing page copy for a developer tool that {one-line value prop}.
Audience: indie hackers and small teams. Sections: hero (headline + sub),
social proof strip, 6-feature grid, 3-step "how it works", pricing with
two tiers (Starter / All-in), FAQ (6 questions), final CTA. Tone: direct,
no hype. Canadian friendly. Keep each section under 120 words.
```

## Launch tweet thread

```
Write a 7-tweet launch thread for a commercial boilerplate {name}.
Audience: Laravel + React indie builders. The product ships {features}.
Thread structure: problem → what it is → top 3 features → who it's for →
pricing → proof/community → CTA. End with the link placeholder [LINK].
```

## Changelog / release notes

```
Write release notes for version {x.y} of a SaaS boilerplate given these
change bullets: {bullets}. Group into Added / Changed / Removed / Fixed,
Keep a Changelog format, developer-facing tone, no marketing fluff.
```
